# 👥 進階好友與群組共享 (Advanced Sharing & Groups) 設計提案

本文件規劃如何擴展 Learn8 的好友、群組與課程系統，讓使用者可以互相分享課程、共同學習以及一同進行競技場對抗。

---

## 🔗 1. 課程卡片分享與好友分享機制

我們決定將 **「分享」** 按鈕整合至每個課程卡片上。

```
+-----------------------------------------------------+
| [📖] Python 進階實戰                                 |
|                                                     |
| (•) 已解鎖關卡: 3/5                                  |
| +-------------------------------------------------+ |
| | [✏️ 編輯]        [🗑️ 刪除]        [📤 分享]       | |
| +-------------------------------------------------+ |
+-----------------------------------------------------+
```

### 1.1 分享操作流程
1. 使用者點擊課程卡片上的 **「📤 分享」** 按鈕，彈出該特定課程的分享 Modal。
2. **第一步：選擇分享對象** - 
   - **好友 (Friends)**：勾選想要分享的好友。
   - **群組 (Groups)**：選擇想要分享的群組。
3. **第二步：發送邀請** - 點擊確定後，後端會向對象發送 SSE 通知或站內信。

### 1.2 接收邀請的通知位置

為了讓使用者不會錯過好友分享的課程，推薦以下位置放置通知：

- **選項一：整合在現有 `/social` 社交頁面 (最推薦)**
  - 在社交分頁的「好友列表」上方，新增一個 **「課程分享邀請 (Course Invitations)」** 區塊。
  - **連動小紅點**：當有未讀的課程分享時，導覽列的 **👥 Social** 按鈕旁會亮起帶數字的小紅點 (Badge)。
- **選項二：整合在 `/courses` (自訂課程頁面)**
  - 在課程清單的最上方，加入一條醒目的橫幅 (Banner) 或清單，例如：
    - `📢 小明 想與您分享課程：[Python 實戰] -> [接受] [拒絕]`
  - **優點**：與使用者的書架（Library）非常接近，點擊接受後，該卡片會當場出現在書架中，視覺效果最流暢。

## 👥 2. 完善的群組功能擴展 (Group Co-learning & Arena)

為了讓群組更具凝聚力，我們強化了兩大核心設計：「群組共讀」與「群組專屬對戰房」。

### 2.1 群組教材庫與共讀模式 (Group Course Library)
在每個群組的頁面中，新增 **「群組教材庫 (Group Library)」**。
- **共享機制**：當群組成員將自己的優質課程分享到群組時，該課程就會進到群組教材庫。
- **匯入學習**：群組內的所有成員都能在該列表點擊「匯入到我的 Library」，開始這門課。
- **共讀進度 (Co-learning Progress)**：
  - 在群組教材庫的每門課程旁邊，成員可以看到組內其他同學對這門課程的學習狀況（如：**成員 A: 50% 已解鎖, 成員 B: 100% 已完成**）。
  - 這能產生良性的學習競爭與互助氛圍。

### 2.2 群組競技場對戰 (Group Arena Matches)
為了實現「大家玩同一個競技場」，我們設計了群組專屬的對戰入口：

```
+-------------------------------------------------------------------------+
|  群組名稱：🔥 終極 Python 學習戰隊                                      |
+-------------------------------------------------------------------------+
|  [📚 群組教材庫]       [⚔️ 群組競技場對抗]      [👥 成員與排行]          |
|                                                                         |
|  目前進行中的競技對戰：                                                 |
|  * 房號 #A8C92 - 模式: 費曼鏡像擂台                                     |
|    - 玩家: 成員 A, 成員 B                                               |
|    - [⚔️ 一鍵加入此對戰房]                                               |
|                                                                         |
|  [➕ 發起新的群組內部對戰房]                                              |
+-------------------------------------------------------------------------+
```

- **房間一鍵顯示**：當任何群組成員在 Arena 中建立私人對戰房時，群組頁面的「群組競技場對抗」會即時更新。
- **一鍵加入機制**：成員點擊「一鍵加入此對戰房」按鈕，前端會直接將成員帶入該對戰房中（`/arena/match/[matchId]`），不需再手動複製或輸入複雜的房間代碼。

## 🛠️ 3. 後端資料模型與 API 設計

### 3.1 課程分享與群組教材表
```python
# app/models/group_course.py
from sqlalchemy import Column, Integer, ForeignKey, DateTime
from sqlalchemy.sql import func
from app.db.base import Base

class GroupCourseModel(Base):
    __tablename__ = "group_courses"

    id = Column(Integer, primary_key=True, index=True)
    group_id = Column(Integer, ForeignKey("groups.id", ondelete="CASCADE"), nullable=False)
    course_id = Column(Integer, ForeignKey("courses.id", ondelete="CASCADE"), nullable=False)
    shared_by_id = Column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False)
    
    created_at = Column(DateTime(timezone=True), server_default=func.now())
```

### 3.2 擴展社交 API 端點 (`/api/v1/social/sharing`)
- `POST /api/v1/social/sharing/friend` - 分享課程給特定好友。
- `POST /api/v1/social/sharing/group` - 分享課程給特定群組。
- `GET /api/v1/social/groups/{group_id}/courses` - 獲取該群組共享的課程庫。
- `POST /api/v1/social/groups/{group_id}/courses/{course_id}/import` - 匯入群組課程到個人 Library。
- `GET /api/v1/social/groups/{group_id}/active-matches` - 獲取群組成員當前正在對戰的競技場房間。

## 🛡️ 4. 系統設計邊界與完善性考量 (Edge Cases & Advanced Details)

為了確保平台的穩定與順暢，我們對以下潛在盲點進行了完善規劃：

### 4.1 課程資料副本問題 (Fork vs. Linked Reference)
- **規則**：當好友或群組成員接受分享時，系統預設採用 **「複製副本 (Fork)」** 模式。
- **優點**：即使原作者事後修改或刪除了自己的自訂課程，也不會影響已經匯入的學生的學習紀錄（如 `LessonAttempt` 與 `StageHistory`）。

### 4.2 創作者更新課程內容的影響範圍
- **規則**：創作者若再次對自建課程編輯或修改，這些變更僅對尚未匯入此課程的新成員生效。
- **提示機制**：在編輯儲存時，前端應彈出提示：「修改課程結構將只對未來的新匯入者生效，現有已學習者的內容不會受影響」。

### 4.3 審核發佈後的隔離與版本控制
- **規則**：管理者點擊「審核通過並發佈為全站官方公開課程」時，後端導出的 YAML 為一門課程的**靜態快照**。
- **優點**：發佈後的官方公開課程與原作者在資料庫中的草稿完全解耦，原作者若在自己的頁面刪除該課程，不會影響系統官方教材。

### 4.4 社交與通知機制 (Notification Presence)
- **規則**：分享邀請會直接發送一條帶有「接受/拒絕」按鈕的站內訊息或 SSE 通知。
- **優點**：好友只要點擊一鍵「接受」，就能直接看到新課程出現在自己的 `Your Library` 清單中，達到最流暢的社交傳播體驗。
